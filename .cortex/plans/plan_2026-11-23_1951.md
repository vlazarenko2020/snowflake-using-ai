## Steps
1. **Setup:** `CREATE DATABASE IF NOT EXISTS AVELTO_RENTALS`, then `CREATE SCHEMA IF NOT EXISTS AVELTO_RENTALS.BRONZE`. Everything below goes in that schema.
2. **Stage:** create an internal stage `BRONZE_LANDING_STAGE` and upload the 8 files with `PUT ... AUTO_COMPRESS=FALSE`, so they arrive unchanged.
3. **CSV file format:** `TYPE=CSV`, `PARSE_HEADER=TRUE`, `TRIM_SPACE=FALSE`, `EMPTY_FIELD_AS_NULL=FALSE`, `NULL_IF=()`, `ENCODING=UTF8`. Values are kept as written: no trimming, blanks stay blank, and text like `NULL` or `True` isn't converted.
4. **Seven `bronze_*` tables:** every column is `VARCHAR`, named exactly as in the file header, in lowercase with quoted identifiers. This keeps values like `1.0`, `True`, phone formats and dates exactly as written. Load each with `COPY INTO ... MATCH_BY_COLUMN_NAME=CASE_SENSITIVE, ON_ERROR=ABORT_STATEMENT`.
5. **JSON:** create `bronze_bookwave_reservations_raw (raw VARIANT)`. Because the file is one wrapper object, the usual array-splitting load option can't split it. Instead I'll run `INSERT INTO ... SELECT f.value FROM @stage/reservations_export.json (FILE_FORMAT=>json_fmt), LATERAL FLATTEN($1:records) f`. This splits only the top-level records array into 2000 rows and keeps each reservation whole, including `paymentDetails`. The wrapper's metadata fields won't be in the table, but the original file stays in the stage.
6. **Verify:**

   - `DESCRIBE TABLE` column names match each CSV header.
