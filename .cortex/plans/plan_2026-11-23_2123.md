## Decisions and assumptions
- **First payment only:** I use `paymentDetails[0]` rather than `LATERAL FLATTEN`. This keeps one row per reservation as you asked. If a reservation ever has several payments, only the first is kept. The alternative is to sum the amounts or switch to one row per payment.
- **Bad dates become NULL:** `TRY_TO_DATE` turns an unparseable date into NULL instead of failing the refresh.
- **Refresh mode:** `REFRESH_MODE = AUTO`, which should resolve to incremental.
- **Schema:** the table goes in a new `SILVER` schema rather than PUBLIC.
